## Why

RAG retrieval for question generation currently pulls from a single undifferentiated pool per (grade, topic, difficulty) — see `SemanticSearchService.SearchFilters` in `api/src/app/opensearch/semantic-search.service.ts`. Within one category (e.g. `number-operations`) and difficulty tier, questions can span many distinct "flavors" (counting, skip-counting, word problems, comparisons, etc.), but retrieval has no way to distinguish them, so generated sets tend to cluster around whatever style is most represented in the index rather than covering the full variety a category/difficulty pairing should offer. Introducing admin-defined sub-categories, tagged onto indexed questions and scoped to (category, difficulty), lets retrieval systematically pull examples from every known sub-category and lets the LLM generate a balanced spread across them — directly improving retrieval coverage and generated-question variety.

## What Changes

- New sub-category taxonomy: a sub-category is scoped to a (question category, difficulty level) pair and carries a required short `description` explaining what it covers. Admin/Teacher users can list, create, update the description of, and delete sub-categories for a given category+difficulty from the question create/edit UI (inline creation, no separate admin screen required).
- `Question` schema (`api/src/app/questions/schemas/question.schema.ts`) gains a `subCategories: string[]` field so a question can be tagged with zero or more sub-categories; Admin/Teacher can add/remove tags on a question during create/edit.
- New CRUD API (`SubCategoriesController`/`SubCategoriesService` + Mongo collection) for managing sub-categories, mirroring existing `questions` module conventions.
- OpenSearch index mapping (`vector-index.service.ts`) gains a `metadata.subCategory` keyword field; existing indexed documents are backfilled/reindexed where a sub-category tag exists.
- `SemanticSearchService.SearchFilters` gains a `subCategory` filter (same pattern as the existing `difficulty` hard filter added in `fix-rag-question-generation`).
- Generation flow (`math-question-generator.service.ts` / `ollama.service.ts`) changes from a single RAG retrieval per (grade, topic, difficulty) call to iterating over every sub-category available for the requested category+difficulty, retrieving a sub-category-scoped RAG pool for each, and generating questions per sub-category so the resulting batch is distributed across the full known taxonomy instead of one mixed pool.
- Each sub-category's `name` and `description` are passed into the LLM prompt directly as explicit generation guidance (not just used to filter RAG retrieval), so generated questions stay aligned with the intended sub-category even when that sub-category has few or no indexed RAG examples yet — the exact situation where mismatched/"wrong sub-category" content was being observed.
- Admin/Teacher can backfill or revise a sub-category's `description` after creation via a new update endpoint, surfaced as an inline "add description" affordance in the sub-category picker wherever it's editable (including the question edit screen), so sub-categories created before this addition — and any already tagged on existing questions — can be given a description without deleting and recreating them.
- **BREAKING**: `SemanticSearchService.SearchFilters` gains a `subCategory` field (internal interface, no external consumers found). The batch-generate orchestration changes from one retrieval call to N (one per sub-category); internal callers of `retrieveRAGContext` need review. Public `POST /api/questions/batch-generate` request/response contract impact to be confirmed in design (whether sub-category distribution is automatic or caller-selectable).

## Capabilities

### New Capabilities
- `question-subcategory-taxonomy`: CRUD management of sub-category tags scoped to (question category, difficulty level), and the ability to tag/untag individual questions with one or more sub-categories from the Admin/Teacher question create/edit UI, including inline creation of new sub-categories.
- `subcategory-aware-rag-retrieval`: Generation-time behavior where RAG retrieval and LLM prompting iterate across every sub-category available for the requested question category + difficulty, pulling sub-category-scoped examples for each and generating questions distributed across the full taxonomy rather than a single mixed pool.

### Modified Capabilities
(none — `openspec/specs/` currently has no existing capability specs to modify; this change introduces the taxonomy and retrieval behavior as new capabilities)

## Impact

- **Affected code**: `api/src/app/questions/schemas/question.schema.ts` (new `subCategories` field + index), new sub-category module under `api/src/app/` (schema/service/controller/DTOs, including the new `description` field and `PATCH /api/subcategories/:id` update endpoint), `api/src/app/opensearch/vector-index.service.ts` (index mapping), `api/src/app/opensearch/semantic-search.service.ts` (`SearchFilters`, `buildFilterClauses`), `api/src/app/ai/ollama.service.ts` (per-sub-category retrieval/generation loop, plus a new sub-category description prompt section) and `api/src/app/math-questions/services/math-question-generator.service.ts` (resolves and passes `{name, description}` per assignment), `apps/admin-app/src/app/features/create-question/create-question.ts`, `apps/admin-app/src/app/features/generate-questions/generate-questions.ts`, and `apps/admin-app/src/app/features/question-detail/question-detail.ts` (shared sub-category picker: tag/create UI plus inline description backfill).
- **Affected systems**: MongoDB (new collection, `questions` schema change), OpenSearch (`math-questions` index mapping change + backfill/reindex of existing documents), Ollama prompt assembly (per-sub-category prompt sections).
- **Testing impact**: new CRUD tests for sub-category API (including description validation on create/update), updated RAG/semantic-search tests (`scripts/test-semantic-search.ts`, `scripts/test-filters.ts`) to cover `subCategory` filtering, admin UI tests for tag add/remove/create/description-backfill flows, and a prompt-assembly test verifying the sub-category focus section is included with and without RAG examples.
- **No removal of existing filters** — grade/topic/difficulty filtering (including the `difficulty` hard filter from `fix-rag-question-generation`) is retained; `subCategory` is additive.
